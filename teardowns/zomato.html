Teardown · Zomato

Discovery → decision → order

How could Zomato improve the restaurant discovery → decision → ordering journey?

Product overview

Zomato is a food ordering and restaurant discovery surface. The job is not "browse restaurants" — it is "decide what to eat, then complete an order with acceptable time, price, and trust."

Target user

Hungry, time-constrained users (often repeating a small set of cuisines) plus occasional explorers. Decision fatigue is the default state.

User journey

Open app / search / location ↓ Feed of restaurants, ads, offers ↓ Filter, compare ratings, delivery time ↓ Menu, cart, upsells ↓ Checkout, tracking

What works

  • Strong local inventory and delivery promise.
  • Ratings, photos, and offers reduce some uncertainty.
  • Reorder and search help repeat users skip discovery.

Pain points

  • Home can feel like a marketplace of competing CTAs rather than a decision aid.
  • Comparing two restaurants (time vs price vs rating) takes too many taps.
  • Menu → cart still fights upsells when the user already decided.

Opportunities

  • "Decide for me" based on time remaining + last 5 orders, with an easy reject.
  • Side-by-side compare for two shortlisted restaurants.
  • Quiet checkout path that defers offers until after place-order.

Prioritization

P0: faster decision for repeat users (high frequency). P1: compare two shortlists. P2: quieter checkout. I would not add more promotional modules to home first — that likely slows decide time.

Experiment

Hypothesis: a "likely order" card on home (from history + ETA) reduces time-to-cart for returning users without lowering AOV (guardrail: attach rate of extras).

Metrics

  • Time to first restaurant tap, time to cart, checkout completion
  • Search vs feed mix, filter usage
  • Guardrails: AOV, offer attach, session bounce
